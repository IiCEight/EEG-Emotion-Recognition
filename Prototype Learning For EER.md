# General Prototype Learning

## Basic model
### Normal Steps

First use GCN to extract the feature.

After get feature of source and target, use a shared Classifier to classify. This Classifier is just a simple linear layer.
```python
class ClassClassifier(nn.Module):
    def __init__(self, feature_dim, num_cls):
        super(ClassClassifier, self).__init__()
        self.classifier = nn.Linear(feature_dim, num_cls)

    def forward(self, x):
        return self.classifier(x)
```

Now we have the source class logits and target class logits.

For source class logits, we calculate the cross entropy directly on the **smooth** source label.

```pyhon
criterion = _LabelSmoothingCE(classes=num_classes).to(device)
cls_loss = criterion(src_out, src_label)
```


At this point we already have target logits from the shared classifier. However, **this is not sufficient on its own**. The classifier was trained purely on source data, so its decision boundary is biased toward the source distribution. Directly using its output as target pseudo-labels would be unreliable — especially early in training when the feature space has not yet been adapted.

This motivates the use of **prototype learning**: instead of relying solely on the classifier, we build class representatives directly from the feature space and use similarity to those representatives as a more reliable pseudo-label signal.


### Critical Steps
The important step is how to get the pseudo label for target data.


This paper uses prototype learning. 
Prototype is the centroid of extracted feature with the same class.
$$
\mu_i = \sum_{x_j \in C_i}f_j
$$
where $C_i$ means the $i$ class emotion.

So we can use all the source feature to get the source prototype
$$
\mu_i^s = \sum_{f_j^s \in C_i^s}f_j^s
$$$f_j^s \in C_i^s$ means the true label of sample $i$ is $i$ class.

The the prototype of each class can be regard as the representation of corresponding class.
We calculate the the similarity between the sample feature and the prototype, and assign the class of the most similar prototype. Here we use inner product to calculate the similarity.
```python
src_sim = torch.mm(
            output_f.to(self.device),
            F.normalize(prototypes.to(self.device), p=2, dim=1).T
        ) / self.tem
```

The results of similarity itself can be used as the final predict label. But PCL model doesn't use it. PRPL does.


**The problem is how to calculate the target prototype which is a common place to innovate.**

**The basic idea is that use the target feature which is confident.** Since we have the predict label generated by the shared classifier (i.e., used to predict the source data label), we can use a subset of all target feature,
$$
F^t_{sub} = \{f_i^t | \max(\text{classifier} (f_i^t)) \ge \gamma \} \subset F^t = \{f_i^t\}
$$
The predict probability of feature which is generated by shared classifier on this subset must greater than or equal to some threshold $\gamma$.

For example, if the output of classifier for target feature $f_i^t$ is `[0.34, 0.34, 0.33]`. That means the classifier is confused about its class,  so it is not selected ($f_i^t \notin  F_{sub}^t$). But if the output of classifier for target feature $f_i$ is `[0.94, 0.02, 0.04]`, this means the classifier is confident about its class, so it is selected ($f_i^t \in  F_{sub}^t$).

After get the selected subset of target feature, we can use its predicted label generated by shared classifier to calculate the target prototype
$$
\mu_i^t = \sum_{f_j^t \in F_{sub}^t\cap C_i^t}f_j^t
$$
**$f_j^t \in C_i^t$ means the predict label of sample $i$ is $i$ class, since we don't have its true label.**

Great! After get the target prototype we can calculate the similarity between target feature and target prototype and use the similarity as the pseudo logits (pseudo label). Then calculate the cross entropy loss using this logits.

```python
target_loss = criterion(tgt_sim, tgt_cluster_label.long())
```

### Boost Factor

However, there is still a problem: **early in training, the feature extractor is poorly initialized**, so the target prototypes and pseudo-labels are noisy and unreliable. Applying `target_loss` with full weight from epoch 0 would let these noisy labels corrupt the model before it has learned anything useful.

The solution is a **boost factor** that gradually increases the weight of `target_loss` over training:

$$\lambda(t) = 2 \cdot \left(\frac{2}{1 + e^{-t/T}} - 1\right)$$

where $t$ is the current epoch and $T$ is the total number of epochs.

```python
boost_factor = 2.0 * (2.0 / (1.0 + math.exp(-epoch / 1000)) - 1)
loss = cls_loss + transfer_loss + boost_factor * target_loss
```

At epoch 0, $\lambda \approx 0$ — target pseudo-labels have no influence. As training progresses, the feature space becomes more discriminative and the prototypes become more reliable. By late training, $\lambda \rightarrow 2.0$, giving the target supervision full weight.

This design ensures that **pseudo-labels only contribute when they are trustworthy**, preventing a feedback loop where noisy labels reinforce bad representations.


## PCL

PCL follows the same basic structure. The differences are in how target prototypes are computed and the addition of extra loss terms.

### Target Prototype: Memory Bank + K-Means

The basic model uses the classifier's output directly on the current batch to select confident samples. PCL replaces this with a **memory bank** — a stored copy of features and scores for every target sample, updated each batch.

```python
target_f_bank     : [target_num, 64]   # normalized target features (all samples)
target_score_bank : [target_num, 3]    # softmax scores (all samples)
```

Each forward pass overwrites the bank entries for the current batch indices. At any point in training, the bank holds the most recent features for every target sample.

The confidence-based filtering then operates over the **entire target dataset**, not just the current batch:

$$F^t_{sub} = \text{top-}k\% \text{ of } \{f_i^t\} \text{ by } \max(\text{score\_bank}_i)$$

PCL uses $k = 30\%$ (top-30% most confident samples across the whole dataset).

Instead of using the classifier's predicted class to assign samples to prototypes, PCL runs **K-Means** ($k=3$) on $F^t_{sub}$ directly — the cluster centers become the target prototypes. This is fully unsupervised and avoids relying on the potentially biased classifier for cluster assignment.

**Why this is better than the basic approach**: The basic model selects confident samples per-batch, which is noisy. The memory bank gives a global, stable view of the entire target distribution, and K-Means finds natural clusters in the feature space without depending on classifier predictions.

---

### Additional Loss: Cross-domain Entropy

Beyond the standard `cls_loss + transfer_loss + boost_factor * target_loss`, PCL adds four extra similarity terms to further shape the feature space geometry.

For each combination of feature domain (source/target) and prototype domain (source/target):

| Variable | Feature | Prototype |
|---|---|---|
| `s2s` | source | source prototypes |
| `t2t` | target | target prototypes |
| `s2t` | source | target prototypes |
| `t2s` | target | source prototypes |

Each gives a softmax similarity distribution `[B, 3]`. PCL minimizes the **entropy** of all four:

$$\mathcal{L}_{entropy} = H(s2s) + H(t2t) + H(s2t) + H(t2s)$$

- `s2s` and `t2t` enforce **within-domain compactness** — features cluster tightly around their own prototypes
- `s2t` and `t2s` enforce **cross-domain alignment** — source features confidently match target prototypes and vice versa

```python
loss = cls_loss + transfer_loss + source_loss
     + boost_factor * target_loss
     + 0.2 * (cross_domain_loss + in_domain_loss)
```

The weight `0.2` keeps these as soft regularizers rather than dominant terms.

---

### Source Confidence Filtering

PCL also applies a confidence filter to the **source** supervision, on top of the standard `cls_loss`:

```python
mask = max(softmax(src_output)) > 0.7
source_loss = criterion(src_prob[mask], src_label[mask])
```

This discards source samples where the model is uncertain, focusing supervision on clean, high-confidence source predictions.

## PRPL

PRPL differs from both the basic model and PCL in two fundamental ways: it replaces the simple linear classifier with a **low-rank bilinear classifier**, and it replaces the cross-entropy-on-pseudo-labels approach with a **pairwise similarity loss**.

### Classifier: Low-rank Bilinear (LabelClassifier)

Instead of a linear layer, PRPL uses a bilinear projection:

$$
S = U^TV\\
\text{logits} = f^\top S P^\top

$$

where:
- $f \in \mathbb{R}^{64}$ is the sample feature
- $U, V \in \mathbb{R}^{32 \times 64}$ are learnable low-rank matrices
- $S$ is the bilinear map matrix
- $P \in \mathbb{R}^{3 \times 64}$ is the **prototype matrix** — one row per class

$U$ projects the feature into a low-rank space. $V P^\top \in \mathbb{R}^{64 \times 3}$ projects each class prototype into the same space. The dot product between them gives the similarity score for each class.

**So if $S = I$, then the bilinear map becomes inner product, so it's just a special way to calculate the similarity between prototype and feature to get the logits.**

**This directly couples the classifier weights to the prototype matrix** — unlike the basic model where the classifier and prototypes are separate.

---

### Prototype Matrix P: Source-Only, Batch-wise Update

Unlike the basic model and PCL, **PRPL has no target prototype**. $P$ is built exclusively from labeled source data and updated every forward pass using only the current source batch.

$P$ is not learned by gradient descent. It is recomputed each batch from the current source batch features $F_s \in \mathbb{R}^{B \times 64}$ and one-hot labels $Y_s \in \mathbb{R}^{B \times 3}$:

$$P = (D + I)^{-1} \cdot Y_s^\top F_s$$

where $D = \text{diag}(Y_s^\top \mathbf{1})$ counts samples per class in the batch. The $+I$ regularization prevents singularity when a class happens to have no samples in the batch.

This is a **closed-form weighted average**: $P_i$ is approximately the mean of source features in class $i$ within the current batch — the standard prototype definition, **but computed fresh each forward pass from batch features rather than accumulated over the whole dataset (Big different from PCL)**.

Since $P$ is built only from source labels, the target domain has no direct influence on the prototypes. Target alignment happens entirely through the pairwise cluster loss and DANN, not through the prototypes themselves.

To keep $P$ well-conditioned, PRPL also adds an **orthogonality loss**:

$$\mathcal{L}_P = \|P^\top P - I\|_F$$

This penalizes class prototypes from becoming collinear, keeping the 3 class directions maximally separated in feature space.

---

### Loss: Pairwise Similarity (PairLoss)

Instead of cross-entropy on pseudo-labels, PRPL uses a **pairwise BCE loss** on the cosine similarity matrix between samples.

For source samples, build the $B \times B$ cosine similarity matrix between logits:

$$S^s_{ij} = \frac{\text{logits}_i \cdot \text{logits}_j}{\|\text{logits}_i\| \|\text{logits}_j\|}$$

and the ground-truth similarity matrix from one-hot labels:

$$\hat{S}^s_{ij} = \frac{y_i \cdot y_j}{\|y_i\| \|y_j\|} \quad \in \{0, 1\}$$

Two samples from the same class have $\hat{S}_{ij} = 1$; different classes give $0$. The loss is:

$$\mathcal{L}_{clf} = -\frac{1}{B^2}\sum_{ij} \left[\hat{S}^s_{ij} \log S^s_{ij} + (1 - \hat{S}^s_{ij}) \log(1 - S^s_{ij})\right]$$

**Why pairwise instead of cross-entropy?** Cross-entropy penalizes each sample independently against its label. Pairwise loss penalizes the *relational structure* — same-class samples should have high mutual similarity, different-class samples should not. This directly encourages compact, well-separated clusters in feature space.

---

### Target Loss: Threshold-based Pairwise Selection

For target samples (no labels), PRPL cannot build a ground-truth similarity matrix.

Instead, it uses the **predicted logit similarity** as a proxy, but only for confident pairs:

**So the pesudo label is generated by similiarity between target feature and source prototype!!!**

$$\text{indicator}_{ij} = \mathbb{1}[S^t_{ij} > \gamma_{\text{upper}}] + \mathbb{1}[S^t_{ij} < \gamma_{\text{lower}}]$$

Pairs with similarity above $\gamma_{\text{upper}}$ are treated as **same-class** (confident positives). Pairs below $\gamma_{\text{lower}}$ are treated as **different-class** (confident negatives). Ambiguous pairs in between are ignored.

$$\mathcal{L}_{cluster} = \frac{\sum_{ij} \text{indicator}_{ij} \cdot \text{BCE}(S^t_{ij},\ \hat{S}^t_{ij})}{\sum_{ij} \text{indicator}_{ij}}$$

**Annealing thresholds**: $\gamma_{\text{upper}}$ starts at 0.9 and decreases each epoch; $\gamma_{\text{lower}}$ starts at 0.5 and increases. They converge toward a common midpoint. This means early training only uses very confident pairs, and later training gradually accepts more borderline pairs as the feature space improves.

---

### Boost Factor

PRPL uses a **linear** boost factor rather than the sigmoid ramp:

$$\lambda(t) = \frac{t}{T} \times 2.0$$

```python
boost_factor = cluster_weight * ((epoch + 1) / max(1, epochs))  # cluster_weight=2.0
```

It grows linearly from 0 to 2.0, giving the cluster loss full weight by the last epoch.

### Total Loss

```python
loss = cls_loss
     + 1.0 * transfer_loss
     + 0.01 * p_loss
     + boost_factor * cluster_loss
```

| Term | Purpose |
|---|---|
| `cls_loss` | Pairwise BCE on source — compact same-class, separate different-class |
| `transfer_loss` | DANN adversarial — domain-invariant features |
| `p_loss` | Orthogonality of $P$ — keep class prototypes well-separated |
| `cluster_loss` | Pairwise BCE on confident target pairs — self-supervised target structure |

## ADANN

ADANN is the simplest of the three models. It has **no prototype matrix and no pairwise loss**. Instead it maintains two explicit prototype vectors per class — one for source, one for target — and updates them via EMA each batch. Classification at test time is pure nearest-prototype in a projected space.

### Prototypes: Explicit EMA Vectors

ADANN stores two sets of prototype vectors directly as buffers:

```python
mu_s : [num_classes, 64]   # source class prototypes
mu_t : [num_classes, 64]   # target class prototypes
```

These are not computed inside the forward pass. They are initialized once before training and then updated every batch outside the gradient graph.

---

#### Initialization

**Source prototypes `mu_s`** use ground-truth labels directly:


Mean of L2-normalized source features per class, then L2-normalize again.

**Target prototypes `mu_t`** have no labels, so a two-step bootstrap from `mu_s` is used:

1. Project all target features: $p_t = \text{projector}(f_t)$
2. Compute similarity to source prototypes and get confidence:
$$\text{prob}_i = \text{softmax}\left(\frac{\text{sim}(p_t,\ p_{\mu_s})}{\tau}\right), \quad \text{confidence}_i = \max_c\ \text{prob}_{ic}$$
3. Keep only reliable target samples: $F^t_{rel} = \{f_i^t \mid \text{confidence}_i > 0.7\}$
4. Assign pseudo-label via source prototype: $\tilde{y}_i^t = \arg\max_c\ \text{prob}_{ic}$
5. For each class $c$: mean of reliable target features with pseudo-label $c$:


So **`mu_t` is bootstrapped entirely from `mu_s`** — target samples are labeled by their nearest source prototype, filtered by confidence, then averaged.

**This is the same stratgy of general model**

---

#### Per-batch EMA Update

After each optimizer step, both prototypes are updated **without gradient** using EMA:

$$\mu \leftarrow \gamma \cdot \mu + (1 - \gamma) \cdot \hat{\mu}$$

where $\hat{\mu}^c$ is the batch mean of features assigned to class $c$.

**For `mu_s`**: **batch** mean of source features per predicted class (argmax of source similarity).

**For `mu_t`**: batch mean of a **mixed** set — two types of samples contribute:

- **Reliable target samples**: $f_t$ with confidence > threshold (pseudo-labeled via source prototypes)
- **Aligned source samples**: $f_s$ where the source sample's **similarity** on `mu_t` matches its true label


**Why mix source samples into `mu_t`?** Early in training, reliable target samples are few and noisy. Source samples that are already consistent with the current `mu_t` provide a stabilizing signal — if a source sample (with a known label) already agrees with what the target prototypes predict, it reinforces those prototypes. As training progresses and `mu_t` improves, more target samples become reliable and the source contribution diminishes relatively.

---

#### Adaptive Gamma

$\gamma$ is not fixed. It is computed each batch from the **agreement** between two sets of target predictions:
- $\hat{y}^{s}$: target predicted via source prototypes `mu_s`
- $\hat{y}^{t}$: target predicted via target prototypes `mu_t`

$$\text{agreement} = \frac{1}{B}\sum_i \mathbb{1}[\hat{y}_i^s = \hat{y}_i^t]$$

$$\gamma = \text{clip}\left(\frac{1}{18.82 \cdot \text{agreement} - 20} + 1.05,\ 0,\ 0.99\right)$$

| Agreement | $\gamma$ | Effect |
|---|---|---|
| High (both sets agree) | Close to 1 | Slow update — prototypes are stable, trust them |
| Low (sets disagree) | Smaller | Fast update — prototypes are inconsistent, adapt quickly |

This self-regulates momentum: when source and target prototypes give the same predictions, the feature space is well-aligned and the prototypes should be trusted. When they disagree, the current batch carries new information that should be incorporated more aggressively.



### Projector

Unlike PCL and PRPL which classify in the 64-d feature space directly, ADANN adds a separate **projection head**:

```python
projector = nn.Linear(64, 32, bias=False)
```

All similarity computations and prototype comparisons happen in this 32-d projected space, not the 64-d feature space. The feature extractor and projector are decoupled — the domain discriminator operates on the 64-d features while classification operates on the 32-d projections.

---

### Loss Terms

```python
loss = w_s * loss_s + w_t * loss_t + w_cond * loss_cond + loss_dann + lambda_f_norm * f_norm_loss
```

| Term | Description |
|---|---|
| `loss_s` | CE on source: similarity between projected source features and projected `mu_s` |
| `loss_t` | CE on reliable target: similarity between projected target features and projected `mu_t`, only for samples with confidence > threshold |
| `loss_cond` | CE on prototype alignment: similarity matrix between `mu_s` and `mu_t` should be identity — each source class prototype should be closest to its corresponding target prototype |
| `loss_dann` | DANN adversarial with fixed GRL alpha=1.0 |
| `f_norm_loss` | Frobenius norm of projector weights — weight decay on the projection |

**`loss_cond` is the key unique term**. It builds a $C \times C$ similarity matrix between all source and target prototypes, then treats the diagonal as the ground truth labels:

$$\mathcal{L}_{cond} = \text{CE}\left(\frac{\text{sim}(\mu_s, \mu_t)}{\tau},\ [0, 1, \ldots, C-1]\right)$$

This forces `mu_s[i]` to be most similar to `mu_t[i]` for every class $i$. Without it, DANN only aligns the **marginal** distributions — source and target features overall. Two classes could silently swap positions between domains and DANN would still be satisfied. `loss_cond` prevents this by explicitly pinning each source class center to its corresponding target class center.

**Threshold annealing**: The confidence threshold for reliable target samples starts at `THRESHOLD_BASE + THRESHOLD_SPAN = 0.7` and decays linearly to `THRESHOLD_BASE = 0.4` over training — same idea as PRPL's threshold annealing but in reverse (starts strict, becomes more permissive).

---

### Prediction

At test time, similarity to `mu_t` is used by default. If the target prototypes have **collapsed** (off-diagonal mean cosine similarity > 0.98, meaning all class prototypes point in nearly the same direction), it falls back to `mu_s`:

```python
phi_mu = phi_mu_s if collapse_score > 0.98 else phi_mu_t
preds = argmax(normalize(phi_f) · normalize(phi_mu).T)
```

This collapse detection prevents silent failure when target prototype estimation goes wrong.

---

### Key Difference from PCL and PRPL

| Aspect | ADANN | PCL | PRPL |
|---|---|---|---|
| Prototype storage | Explicit EMA vectors `[C, 64]` | Memory bank `[N, 64]` | Batch mean matrix `[C, 64]` |
| Target prototype update | EMA with adaptive gamma | K-Means on top-30% | None (source-only) |
| Classification loss | CE on prototype similarity | CE on pseudo-labels | Pairwise BCE |
| Prototype alignment | Explicit `loss_cond` | Implicit via entropy terms | None |
| Prediction | Nearest prototype in projected space | Direct classifier | Cluster label mapping |
